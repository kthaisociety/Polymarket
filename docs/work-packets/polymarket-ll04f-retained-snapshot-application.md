## Candidate memo

### Exact question and ancestry

Can the single LL-04d activity rule improve one exact H3 or H5 touch-replay parent across explicitly
ordered collector blocks and markets under the already fixed LL-04e standard?

Each market binding carries the complete H3 or H5 parent definition and one retained snapshot
reference. Each block carries its exact aware half-open interval. The application plan binds the
environment, scope authority, shared market-independent parent recipe, one parent kind, the exact
LL-04d policy, and exact LL-04e standard. It neither chooses values nor fits state.

### Transformation and target path

For every plan binding, the application must:

1. verify and load canonical retained bytes by SHA-256 and size;
2. require exact environment, scope, block interval, and two-leg parent equality;
3. replay and register the dual-clock L2 state;
4. run the unchanged H3 or H5 parent screen;
5. derive causal LL-00 features with the LL-04d recent window;
6. derive the exact parent-bound LL-04d gate and run LL-04a/b rivals;
7. aggregate the plan's unchanged chronological blocks through LL-04c;
8. apply LL-04e and retain insufficient, rejected, or paper-study status.

The target/outcome, maturity, holding period, costs, missingness, and touch semantics remain those
of the exact parent definition. No intermediate may impute outcomes or relabel displayed touches as
fills.

### Baselines, stopping rule, and recommendation

LL-04b's ungated, complete-history, quiet-only, recent-activity-only, and joint populations remain
the mandatory baselines. LL-04e remains the only stopping rule. Any input identity mismatch fails;
insufficient evidence remains an ordinary assessment, not an operational error. Recommendation
before production snapshots: `EVALUATE` the exact precommitted plan; do not infer usefulness from
synthetic composition tests.
