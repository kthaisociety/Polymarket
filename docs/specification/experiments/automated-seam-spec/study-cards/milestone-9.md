# Milestone-9 study cards

## learning.reflect-history — Trajectory + ResearchLedger outcomes → reflection output

**Why does it exist?** Synthesize cross-task operational and scientific history without treating history or reflection itself as validated learning.

**Which fundamental does it protect?** `CONSISTENT`.

**What must cross?** Source identities/periods/status, failures/rejections, exposure, uncertainty, scope and provenance.

**Most dangerous false success?** Ignore rejected/failed history.

**Which test catches it?** Paired histories differing in failures/status, source-blind consumer/ref audit, denied-source sentinel. **Level C.**

**Any unresolved human decision?** None.

## learning.propose-lesson — reflection output → CandidateLesson

**Why does it exist?** Turn a provisional reflection into an explicit scoped knowledge/procedure proposal with evidence, rather than silently writing memory.

**Which fundamental does it protect?** `CONSISTENT`.

**What must cross?** Lesson meaning/type/scope, supporting/contrary evidence, periods/tasks/environments, caveats, reflection/provenance.

**Most dangerous false success?** Persist reflection text directly as validated memory.

**Which test catches it?** Omit source/scope/type in turn; require no valid candidate. Same text/different evidence identity. **Level A/B.**

**Any unresolved human decision?** None.

## learning.validate-lesson — CandidateLesson + independent evidence/authority → lesson validation decision

**Why does it exist?** Prevent a lesson or benefiting agent from self-promoting unsupported cross-task learning.

**Which fundamental does it protect?** `CONSISTENT`.

**What must cross?** Lesson/type/scope, candidate and independent evidence periods/tasks, caveats, standard/version, validator.

**Most dangerous false success?** Treat original reflection evidence as independent validation.

**Which test catches it?** Beneficiary/self-validator and evidence-overlap fixtures; scope/caveat equality. **Level A/B.**

**Any unresolved human decision?** None; validation standard is predeclared input.

## learning.promote-lesson — promoting lesson decision → validated Memory or Skill

**Why does it exist?** Change epistemic status while preserving exact scope, provenance and knowledge-versus-procedure distinction.

**Which fundamental does it protect?** `CONSISTENT`.

**What must cross?** Lesson meaning/type/scope/applicability, evidence periods/tasks, caveats, provenance, decision/authority/version.

**Most dangerous false success?** Publish both types as undifferentiated prompt text.

**Which test catches it?** Type-paired candidates, scope/caveat preservation, mutation/version tests. **Level A/B.**

**Any unresolved human decision?** None.

## ledger.record-rejected-lesson — rejected lesson decision → append-only ResearchLedger record

**Why does it exist?** Preserve rejected learning and evidence so failed lessons are not erased or repeatedly rediscovered as fresh.

**Which fundamental does it protect?** `CONSISTENT` (MEDIUM).

**What must cross?** Lesson/type/scope, evidence, standard, reasons, decision/authority, environment/time.

**Most dangerous false success?** Persist only promoted lessons.

**Which test catches it?** Reload full rejection ancestry and attempt deletion; future revised candidate retains parent. **Level A/B.**

**Any unresolved human decision?** None.

## learning.publish-to-knowledge — validated Memory/Skill → KnowledgeEnvironment

**Why does it exist?** Publish approved learning for scoped retrieval without granting it universal or current authority.

**Which fundamental does it protect?** `CONSISTENT`.

**What must cross?** Memory/Skill identity/type/content, scope/applicability, caveats, evidence/provenance, version/currentness, permissions.

**Most dangerous false success?** Ignore applicability and inject entry globally.

**Which test catches it?** Validated/rejected and in/out-of-scope pairs, supersession/currentness retrieval. **Level A/B.**

**Any unresolved human decision?** None.

## learning.influence-future-research — permitted validated learning → future ContextPacket and changed behavior

**Why does it exist?** Prove validated learning—not merely its ID—can influence a later task while respecting scope, currentness, permissions and no hidden side channel.

**Which fundamental does it protect?** `CONSISTENT`: implied composite uniquely follows validated-learning architecture.

**What must cross?** Lesson content/type/scope/caveats/provenance/status, future task relation, permissions and exact identity.

**Most dangerous false success?** Drop lesson payload and choose action by presence of ID.

**Which test catches it?** Paired fresh sessions, transcript deletion, fail-on-KnowledgeEnvironment access, third sentinel/out-of-scope branch. **Level C.**

**Any unresolved human decision?** None.
