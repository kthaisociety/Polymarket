# Mission: AI Engineering Through a Time-Series Research Agent

## Why
Build the autonomous time-series research agent as a real product while becoming a more capable software developer who can reason about AI systems, specifications, evaluation, tool authority, and scientific correctness. The aim is durable engineering judgment—not merely using an agent to produce code.

## Success looks like
- Explain the repository's architecture and scientific constraints in plain language without relying on the documents.
- Turn an architectural requirement into a small contract, test, implementation, and evaluation loop.
- Decide deliberately which work belongs to deterministic software and which belongs to a model.
- Diagnose AI-system failures using evidence and improve the appropriate layer rather than guessing at prompts.
- Build, review, and eventually ship the research agent while being able to defend the major engineering choices.

## Constraints
- Learn alongside the real repository and connect lessons to the current development stage.
- Keep lessons short, interactive, and cumulative.
- Prefer primary sources, repository evidence, retrieval practice, and concrete exercises.
- Keep all teaching artifacts under `learning/ai-engineering/`.
- Install additional skills only when their workflow solves a concrete learning or project need.

## Out of scope
- Racing through an abstract survey of every AI topic.
- Treating generated code as evidence of the learner's understanding.
- Replacing the repository's locked architecture with a more fashionable design.
