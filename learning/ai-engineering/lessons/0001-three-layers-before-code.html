Three layers before code

Purpose: avoid building the wrong system correctly.

Imagine building a house. The desired life inside it is the goal; the blueprint records constraints; the bricks and wiring are the implementation. Starting with bricks cannot tell you whether the house needed three bedrooms or a laboratory.

An AI project has the same three layers:

1. Product objectiveThe valuable outcome the system must create.
2. SpecificationThe responsibilities, boundaries, decisions, and rules that define an acceptable system.
3. ImplementationThe code, storage, provider, framework, and local mechanisms chosen to realize the specification.

Apply it to this repository

The product is a reusable research kernel that investigates whether information available at time t predicts a target at time t+h. The specification requires temporal validity, provenance, reproducibility, protected evidence, and promotion gates. Python, a database, class names, and a particular model provider are implementation choices unless a higher-authority document locks them.

This distinction is a core AI-engineering habit: models make plausible suggestions, so the surrounding engineering system must preserve intent and make success testable. AI Hero frames successful AI work around clear success criteria and evaluation rather than intuition alone.
